# 10 · 让 Claude Code 和 agy 共享项目上下文：AGENTS.md 单一真相源

> **真实翻车事故**：2026-08-15，我在一个只有 `CLAUDE.md` 的项目里派 `agy` 执行知识库抽取。因为当前目录没有 `AGENTS.md`，agy 根本读不到任何项目隔离规则！它自作主张机械套用了全局配置里“自定义技能需要放入 dotfiles 方便多端同步”的条文，顺手把整个上游项目工具连带生成的知识库，一口气塞进了我的 `~/dotfiles` 仓库，甚至**自动执行 git commit 并且 push 到了我的远程公共仓库**……当场直接吓出一身冷汗！

---

## 痛点：两个顶流 Agent，认的配置文件各不相同

在日常工程实践中，很多团队都会采用“混合双打”模式：
* 偶尔用聪明但昂贵的 Claude Code 做顶层规划；
* 偶尔让包月免费的 `agy` 接管干体力活、或者当接班司机。

但尴尬的现实是：
* **Claude Code 认 `CLAUDE.md`**；
* **agy（Antigravity / Gemini 系列）默认只认 `AGENTS.md`（项目级）和 `GEMINI.md`**。

如果项目里只维护了一份 `CLAUDE.md`，对 `agy` 来说相当于**在完全失控的裸奔状态下跑代码**——所有的目录边界、约定规范、禁止修改的敏感文件，在它眼里全都是空气。

---

## 错误姿势：复制黏贴两份配置文件？

很多人第一反应是：“那我把 `CLAUDE.md` 的内容复制一份改名为 `AGENTS.md` 不就行了？”

**相信我，千万别这么干！**  
只要维护两份平行的规则文件，只要过上两周，两边更新一定会出现分支冲突和认知分歧。

---

## 优雅解法：`AGENTS.md` 做“薄壳”，`CLAUDE.md` 做“唯一真相源”

最聪明的做法是让 `AGENTS.md` 当一个极简的**薄壳指示牌（Thin Shell）**，只负责三件事：
1. 告诉 agy：“正本在 `./CLAUDE.md`，去把它读一遍！”
2. **忽略清单**：把 Claude 专属的能力（比如 TaskCreate 记忆系统、特定子代理）明确列出来让它跳过，免得它自作聪明假装自己能调用。
3. **安全铁律**：重申绝对禁止越界的红线（严禁碰全局目录 `~/dotfiles`）。

### 推荐的 `AGENTS.md` 模板配置

把下面这段直接扔进你的项目根目录 `AGENTS.md`：

```markdown
# AGENTS.md — agy（Antigravity/Gemini）在本项目中的入口规则（薄壳）

> 📢 **单一真相源**：本项目规则正本唯一存放在 `./CLAUDE.md`。本文件不冗余复制业务逻辑，只定义角色映射与安全红线。

### 第一步：请立即完整阅读 `./CLAUDE.md`
所有代码风格、测试规范与项目上下文均以 `./CLAUDE.md` 为准。在阅读过程中，若遇到你无法执行的特有机制，请按以下清单处理：

### 🚫 忽略清单（Claude 专属特权，跳过即可）
- Claude 的 Memory 记忆系统、Sub-Agent（Task/Agent 委托派发机制）、TaskCreate 待办标签
- SessionStart Hook 注入机制、特定 statusLine 自定义字段
- `.claude/skills/` 下的专属命令——若未被当前环境挂载，直接回复不支持，严禁猜测伪造

### 🛡️ 照做清单（全员安全硬指标）
- **产物隔离**：所有生成的临时文件、脚本或新 Skill，**一律留在当前项目工作区内，严禁写入 `~/dotfiles` 或任何外部全局目录**！
- **花钱动作双重确认**：凡涉及调用额外收费 API 或云端部署指令，必须显式向用户求证。
- **实事求是**：遇到前置条件不满足或逻辑歧义，立刻抛出，禁止自行脑补。
```

## 进阶：如何区分“被派活的施工员”与“交互司机”？

如果你的项目已经深度接入了司机施工模式（由 Claude 在后台派发 `scripts/agy-do.sh`），你可以在 `AGENTS.md` 头部加一段**身份判定**：

```markdown
## 身份与模式自适应
- **施工队模式**：如果你是被自动化脚本在 `.worktrees/task-xxx/` 目录中唤醒的，说明当前处于分包施工状态 → **请把注意力完全聚焦在任务卡本身**，无需通读全部架构文档。
- **主驾司机模式**：如果是人类用户直接在项目根目录下敲命令与你对话 → 请严格按照下述规则通读上下文。
```

---

## 总结落地小贴士

* **不要搞全量软链接**：直接 `ln -s CLAUDE.md AGENTS.md` 会把很多 Claude 专有语法原封不动灌给 agy，白白制造 Token 噪音。
* **一个技巧**：如果习惯了使用 `GEMINI.md`，可以在根目录下建一个符号链接 `ln -s AGENTS.md GEMINI.md`，这样无论底层 CLI 优先认哪个名字，读取到的都是这一份干练的薄壳规则。
